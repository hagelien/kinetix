## Structural limitation (why the catalog cannot author the whole registry)

A drug-monograph row is not automatically a runnable model (plan §3). The catalog cannot supply: a first-order absorption rate (`kaPerHour`); inter-compartmental micro-rates or saturable-elimination constants (`k12`/`k21`, `Vmax`/`Km`); a per-route bioavailability split (it carries one absolute F); or clean, unit-consistent values for every analyte (several fields are noisy auto-extractions). So the registry stays hand-authored and reviewed, and this report enforces the guarantee the plan actually needs: no *silent* drift between a shipped parameter and the reviewed catalog.

## DB-derived offline registry artifact (CV-4c-2b-b-2)

`scripts/generate-derived-registry.ts` reads all derivation inputs in the single `REPEATABLE READ` transaction owned by `readDerivedRegistrySnapshot`, then commits a deterministic artifact to `src/lib/kinetics-core/generated-registry.ts`. Run `npm run kinetics:registry` to refresh it and `npm run kinetics:registry:check` for the non-writing live-DB comparison that runs beside this provenance gate in CI.

The artifact contains its checksum, derived tier, override-supersession report, and an explicit `notModelable` report with each omitted entry’s overall and per-route missing/unsupported reasons. The offline loader recomputes the checksum and merges reviewed definitions first, so reviewed overrides always win.

Rollout is opt-in with `VITE_DERIVED_REGISTRY_ENABLED=true`; until enabled, consumers keep the reviewed-only registry while the committed coverage report remains inspectable.
